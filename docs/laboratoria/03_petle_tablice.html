Laboratorium 3

Instrukcje cykliczne i tablice

Wprowadzenie do programowania · C++ · instrukcja laboratoryjna

Cel ćwiczenia: Przetwarzanie serii danych z wykorzystaniem pętli i tablic.

Środowisko: Visual Studio Community, projekt Console App, standard C++17.

Wejściówka

4 pytania wyboru z materiału laboratoriów 1–2, po 1 punkcie, oraz krótki program do ręcznego sprawdzenia. Test wymaga prześledzenia kodu, a nie tylko rozpoznania nazwy konstrukcji. Pętle i tablice nie są jeszcze oceniane.

Pracuj samodzielnie. Przyjmij, że fragmenty pytań wyboru znajdują się wewnątrz poprawnie zdefiniowanej funkcji main i dołączono <iostream>. Analizuj kod dokładnie w zapisanej postaci. Po potwierdzeniu zapisu pojawi się wynik testu wyboru (0–4); kod sprawdzi prowadzący osobno.

1. Powtarzanie znanej liczby operacji — for

Pętla pozwala wielokrotnie wykonać ten sam blok instrukcji. for jest wygodna, gdy znamy liczbę powtórzeń lub kolejne wartości zmiennej sterującej. Zamiast powielać kod, zapisujemy go raz w ciele pętli.

Ogólna postać:

for (initialization; condition; step) {
    // Instructions repeated while condition is true.
}

Inicjalizacja wykonuje się tylko raz, przed pierwszym sprawdzeniem warunku. Jeżeli warunek jest prawdziwy, program wykonuje ciało, następnie krok i ponownie sprawdza warunek. Jeżeli warunek jest fałszywy od początku, ciało nie wykona się ani razu. Dwa średniki rozdzielają części nagłówka; nie dopisujemy średnika za jego zamykającym nawiasem.

Przykład nowej konstrukcji:

for (int i = 0; i < 4; ++i) {
    std::cout << i << '\n';
}

Fragment wypisuje 0, 1, 2 i 3. ++i zwiększa zmienną o jeden, a --i zmniejsza ją o jeden. Można też użyć kroku takiego jak i += 2. Zmienna zadeklarowana w nagłówku jest dostępna w pętli, ale nie po jej zakończeniu.

Zadanie 1. Liczby i ich kwadraty

Napisz program, który w pierwszej pętli for wypisuje liczby od 1 do 10 wraz z ich kwadratami, a w drugiej te same pary w kolejności od 10 do 1. Każdą parę wypisz w osobnym wierszu. Nie używaj dziesięciu oddzielnych instrukcji wypisujących.

Sprawdź: pierwszy raport zaczyna się od pary 1 1 i kończy parą 10 100; drugi ma kolejność odwrotną. Każda pętla wykonuje 10 obiegów.

Wyjaśnij: jaka jest ostatnia wartość zmiennej, przy której wykonuje się ciało każdej pętli? Co zmieni zastąpienie <= 10 przez < 10 w pierwszej pętli?

2. Wynik przechowywany między obiegami — akumulator

Jeżeli kolejne obiegi mają współtworzyć jeden wynik, potrzebna jest zmienna zachowująca wartość pomiędzy nimi. Zmienną gromadzącą sumę nazywamy akumulatorem. Deklarujemy ją przed pętlą i nadajemy jej wartość początkową zero.

Ogólna postać:

int total = 0;
for (initialization; condition; step) {
    total += current_value;
}

total += current_value dodaje bieżący składnik do dotychczasowej sumy. Przypisanie total = current_value zastępowałoby poprzedni wynik. Umieszczenie inicjalizacji total = 0 wewnątrz ciała zerowałoby sumę przed każdym dodaniem.

Przykład nowej konstrukcji:

int total = 0;
for (int value = 2; value <= 6; value += 2) {
    total += value;
    std::cout << value << ": " << total << '\n';
}

Kolejne składniki wynoszą 2, 4 i 6, a sumy po ich dodaniu — 2, 6 i 12. Taki wydruk stanowi ślad obliczeń: pokazuje nie tylko wynik końcowy, ale również sposób jego powstawania.

Zadanie 2. Suma od 1 do N

Wczytaj całkowite N z zakresu 0–100. Dla wartości spoza zakresu wypisz Invalid N i zakończ program. Oblicz sumę liczb od 1 do N w pętli for, bez gotowego wzoru. Wypisz wynik.

Sprawdź: N = 0, 1, 5, 100. Oczekiwane sumy to 0, 1, 15 i 5050. Sprawdź również odrzucenie -1 i 101. Załóż poprawny odczyt liczby całkowitej.

Wyjaśnij: dlaczego dla N równego zero wynik nadal jest poprawny, mimo że ciało pętli się nie wykonuje? Dla N równego 5 zapisz składnik i sumę po każdym obiegu.

3. Powtarzanie zależne od warunku — while

Pętla while jest przydatna, gdy powtarzamy działanie tak długo, jak długo spełniony jest warunek. Liczba powtórzeń może wynikać z przebiegu obliczeń, zamiast być bezpośrednio podana w nagłówku.

Ogólna postać:

while (condition) {
    // Instructions that may change the condition.
}

Warunek jest sprawdzany przed każdym obiegiem. Trzeba zapewnić zmianę danych wpływających na ten warunek, jeśli program ma zakończyć pętlę. Brak takiej zmiany może prowadzić do pętli nieskończonej.

Przykład nowej konstrukcji:

int remaining = 3;
while (remaining > 0) {
    std::cout << remaining << '\n';
    --remaining;
}

Fragment wypisuje 3, 2 i 1. Po ostatnim zmniejszeniu zmienna ma wartość zero i kolejne sprawdzenie kończy pętlę. Gdyby początkowo miała wartość zero, nie zostałby wypisany żaden wiersz.

Zadanie 3. Podwajanie do osiągnięcia progu

Wczytaj całkowity próg limit z zakresu 1–1000; niepoprawną wartość odrzuć komunikatem. Zacznij od wartości 1 i podwajaj ją w pętli while, dopóki jest mniejsza od progu. Zlicz wykonane podwojenia. Wypisz końcową wartość i liczbę podwojeń. Załóż poprawny odczyt liczby.

Sprawdź: dla progów 1, 3, 16 i 17 oczekiwane pary „wartość, liczba podwojeń” to odpowiednio (1, 0), (4, 2), (16, 4) i (32, 5).

Wyjaśnij: dlaczego wartość końcowa może przekroczyć próg? Która instrukcja gwarantuje, że dla dopuszczalnych danych warunek w końcu przestanie być prawdziwy?

4. Wykonanie co najmniej raz — do…while

W do…while warunek jest sprawdzany po wykonaniu ciała. Z tego powodu ciało wykona się przynajmniej raz. Jest to wygodne dla menu: najpierw pokazujemy opcje i odczytujemy wybór, a dopiero potem sprawdzamy, czy użytkownik chce kontynuować.

Ogólna postać:

do {
    // Instructions executed at least once.
} while (condition);

Po nawiasie zamykającym warunek występuje średnik — jest częścią tej konstrukcji. To różnica względem zapisu zwykłej pętli while z blokiem instrukcji.

Przykład nowej konstrukcji:

int answer = 0;
do {
    std::cout << "Enter 0 to finish: ";
    if (!(std::cin >> answer)) {
        return 1;
    }
} while (answer != 0);

Mimo początkowej wartości zero pytanie zostanie wyświetlone. Warunek sprawdzany po odczycie decyduje, czy trzeba zapytać ponownie. return 1; użyte w main kończy cały program w razie błędu odczytu.

Zadanie 4. Menu licznika zgłoszeń

Napisz program z licznikiem początkowo równym zero. W pętli do…while wyświetlaj menu i wczytuj opcję: 1 — zwiększ licznik, 2 — wyświetl licznik, 3 — wyzeruj licznik, 0 — zakończ. Wybór obsłuż przez switch. Inne liczby dają Unknown option, po czym menu pojawia się ponownie. Błąd odczytu kończy program komunikatem Invalid input.

Sprawdź: sekwencja 1 1 2 3 2 0 pokazuje licznik 2, a potem 0. Dla samego 0 menu pojawia się raz. Sprawdź również 9 0 i wpisanie tekstu zamiast liczby.

Wyjaśnij: dlaczego break kończący przypadek w switch nie kończy otaczającej go pętli? Który warunek decyduje o zakończeniu pracy menu?

5. Przerwanie pętli i pominięcie obiegu — break i continue

break kończy najbliższą otaczającą pętlę lub instrukcję switch. continue dotyczy pętli: pomija resztę bieżącego obiegu. W while przechodzi do sprawdzenia warunku, a w for najpierw do kroku, a następnie do sprawdzenia warunku.

Ogólna postać:

while (condition) {
    if (stop_condition) {
        break;
    }
    if (skip_condition) {
        continue;
    }
    // Process the accepted value.
}

continue nie może omijać jedynej instrukcji, która pozwala pętli posunąć się dalej. Jednym ze sposobów uniknięcia tego błędu jest umieszczenie kolejnego odczytu w warunku while.

Przykład nowej konstrukcji:

int value = 0;
while (std::cin >> value) {
    if (value == -1) {
        break;
    }
    if (value < 0) {
        continue;
    }
    std::cout << "Accepted: " << value << '\n';
}

Wartość -1 jest sygnałem końca, a nie elementem danych. Inne wartości ujemne są pomijane. Po continue następna próba odczytu następuje w warunku pętli. Nieudany odczyt również kończy tę pętlę, ponieważ warunek staje się fałszywy.

Zadanie 5. Pomiary do sygnału końca

Wczytuj całkowite poziomy baterii aż do -1 albo nieudanego odczytu. Dopuszczalne pomiary to 0–100. Sprawdzaj -1 przed sprawdzeniem zakresu i użyj break do zakończenia wprowadzania. Pozostałe liczby spoza zakresu pomijaj komunikatem Invalid charge i instrukcją continue.

Zlicz zaakceptowane pomiary i oblicz ich sumę. Nie przechowuj pomiarów w tablicy. Po zakończeniu wypisz liczbę i sumę, a jeśli nie przyjęto żadnego pomiaru — dodatkowo No data.

Sprawdź: 50 0 100 -1 daje 3 pomiary i sumę 150. Sekwencja 20 -2 101 30 -1 daje 2 pomiary i sumę 50. Dla samego -1 liczba i suma wynoszą zero. Przyjmij nie więcej niż 1000 poprawnych pomiarów, aby suma mieściła się w używanym typie int na stanowisku laboratoryjnym.

Wyjaśnij: dlaczego -1 trzeba obsłużyć przed pozostałymi liczbami ujemnymi? Czy pominięty pomiar ma wpływać na licznik lub sumę?

6. Kilka wartości tego samego typu — tablica

Tablica przechowuje ustaloną liczbę elementów tego samego typu. Do poszczególnych elementów odwołujemy się przez nazwę tablicy i indeks w nawiasach kwadratowych. Indeksowanie zaczyna się od zera.

Ogólna postać:

element_type array_name[element_count];
array_name[index] = value;

W zwykłej tablicy C++ używanej w tych ćwiczeniach liczba elementów musi być dodatnią stałą znaną podczas kompilacji. Nie deklarujemy jej rozmiarem wczytanym przez std::cin. Dla tablicy o rozmiarze count poprawne indeksy to od 0 do count - 1. Dostęp poza tym zakresem ma niezdefiniowane zachowanie — nie musi wywołać czytelnego komunikatu błędu.

Przykład nowej konstrukcji:

const int count = 4;
int values[count] = {2, 5, 1, 4};
values[1] = 9;
std::cout << values[0] << " " << values[count - 1] << '\n';

Przypisanie zmienia drugi element na 9. Fragment wypisuje 2 i 4, bo odczytuje pierwszy i ostatni element. Zapis int values[count] = {}; wyzerowałby wszystkie elementy. Samo int values[count]; dla tablicy lokalnej nie zapewnia ich wyzerowania.

Zadanie 6. Odczyt i zmiana elementu

Zadeklaruj tablicę sześciu liczb całkowitych o początkowych wartościach {10, 20, 30, 40, 50, 60}. Wypisz pierwszy i ostatni element, zmień trzeci element na -5, a następnie wypisz drugi, trzeci i czwarty element. W tym zadaniu odwołuj się do konkretnych indeksów, bez pętli.

Sprawdź: pierwszy wydruk zawiera 10 i 60, a drugi 20, -5 i 40. W debuggerze obejrzyj całą tablicę po przypisaniu.

Wyjaśnij: dlaczego trzeci element ma indeks 2? Dlaczego wyrażenie values[6] nie wskazuje ostatniego elementu takiej tablicy? Nie sprawdzaj tego przez celowe wykonywanie odczytu poza zakresem.

7. Przejście przez tablicę w pętli

Zmienna sterująca pętli może pełnić rolę indeksu. Pozwala to tą samą instrukcją wczytywać, wypisywać albo zmieniać kolejne elementy. Pętla musi obejmować wyłącznie poprawne indeksy.

Ogólna postać:

for (int i = 0; i < count; ++i) {
    // Read, display or modify array_name[i].
}

Dla dodatniego count taki nagłówek daje indeksy 0, 1, …, count - 1. Warunek i <= count dopuściłby dodatkowy, niepoprawny indeks. Dla przejścia wstecz przy zmiennej typu int zaczynamy od count - 1 i kończymy po indeksie zero.

Przykład nowej konstrukcji:

const int count = 3;
int values[count] = {4, 7, 2};
for (int i = 0; i < count; ++i) {
    std::cout << i << ": " << values[i] << '\n';
}

Fragment wypisuje pary 0: 4, 1: 7, 2: 2. Na tej samej zasadzie std::cin >> values[i] zapisuje wczytaną liczbę bezpośrednio w bieżącym elemencie.

Zadanie 7. Wczytanie i odwrócona kolejność

Utwórz wyzerowaną tablicę pięciu liczb typu double. W pierwszej pętli wczytaj wszystkie elementy, a w drugiej wypisz je w kolejności odwrotnej do wczytania. Przy każdej wartości wypisz jej oryginalny indeks. Sprawdź powodzenie odczytu; w razie błędu zakończ program komunikatem Invalid input, bez wypisywania niepełnej tablicy.

Sprawdź: dla 2.5 0 -1 8 4 wynik ma obejmować pary 4: 4, 3: 8, 2: -1, 1: 0, 0: 2.5. Sprawdź też pięć jednakowych wartości i tekst zamiast trzeciej liczby.

Wyjaśnij: czy wypisywanie w odwrotnej kolejności zmieniło rozmieszczenie danych w tablicy? Dlaczego przy indeksie typu int warunek i >= 0 pozwala obsłużyć pierwszy element i potem zakończyć pętlę?

8. Suma i średnia tablicy — konwersja przed dzieleniem

Do sumowania elementów wykorzystujemy akumulator oraz pętlę po indeksach. Jeżeli suma i liczba elementów mają typ int, ich iloraz również powstaje przez dzielenie całkowite. Samo zapisanie wyniku w zmiennej double nie przywróci odrzuconej części ułamkowej.

Ogólna postać konwersji:

static_cast<target_type>(expression)

static_cast<double>(total) tworzy wartość typu double odpowiadającą sumie. Nie zmienia typu zmiennej total. Gdy jeden argument dzielenia jest typu double, drugi zostaje do tego typu przekonwertowany i wykonuje się dzielenie zmiennoprzecinkowe.

Przykład nowej konstrukcji:

int total = 7;
int count = 2;
double average = static_cast<double>(total) / count;
std::cout << average << '\n';

Wynik wynosi 3.5. Umieszczenie konwersji dopiero wokół total / count dałoby 3.0, ponieważ dzielenie całkowite nastąpiłoby wcześniej. Liczba elementów musi być niezerowa; w następnych zadaniach tablice mają ustalone dodatnie rozmiary.

Zadanie 8. Suma, średnia i ślad obliczeń

Zadeklaruj tablicę sześciu liczb całkowitych {80, 20, 55, 0, 100, 30}. W pętli oblicz sumę. Po każdym dodaniu wypisz indeks, wartość elementu i aktualną sumę. Po pętli oblicz średnią za pomocą konwersji static_cast<double> przed dzieleniem.

Sprawdź: kolejne sumy to 80, 100, 155, 155, 255 i 285; średnia wynosi 47.5. Następnie sprawdź sześć zer oraz {1, 1, 1, 1, 1, 2} — dla ostatniej tablicy średnia wynosi w przybliżeniu 1.16667 przy domyślnym formatowaniu.

Wyjaśnij: dlaczego static_cast<double>(total / count) nie jest równoważne konwersji samego total przed dzieleniem? Czy liczba elementów równa sześć może dać niecałkowitą średnią mimo całkowitych danych?

9. Minimum, maksimum i pozycja pierwszego wystąpienia

Dla niepustej tablicy można rozpocząć wyszukiwanie minimum od jej pierwszego elementu. Następnie porównujemy kolejne elementy z dotychczasowym kandydatem. Ta metoda nie wymaga zgadywania wartości, która na pewno będzie większa lub mniejsza od wszystkich danych.

Ogólna postać:

int minimum = values[0];
int minimumIndex = 0;
for (int i = 1; i < count; ++i) {
    if (values[i] < minimum) {
        // Save the new minimum and its index.
    }
}

Zaczynamy od indeksu 1, ponieważ element zerowy jest już kandydatem. Przy < równy element nie zastępuje wcześniejszego, więc zachowujemy indeks pierwszego minimum. Przy <= kolejny równy element zastąpi poprzedni i po pełnym przejściu otrzymamy ostatnie wystąpienie. Wyszukiwanie maksimum jest analogiczne, ale kierunek porównania trzeba odwrócić.

Przykład nowej konstrukcji:

const int count = 3;
int values[count] = {8, 3, 6};
int maximum = values[0];
for (int i = 1; i < count; ++i) {
    if (values[i] > maximum) {
        maximum = values[i];
    }
}
std::cout << maximum << '\n';

Fragment wypisuje 8. Inicjalizacja minimum zerem byłaby błędna np. dla samych dodatnich danych; inicjalizacja maksimum zerem byłaby błędna dla samych ujemnych. Odczyt values[0] wymaga niepustej tablicy.

Zadanie 9. Ekstrema i remis

Dla tablicy sześciu liczb oblicz minimum, maksimum i indeks pierwszego minimum. Każdy wynik wyznacz na podstawie danych, bez wpisywania odpowiedzi na stałe i bez sortowania tablicy.

Sprawdź:

Tablica Minimum Maksimum Indeks pierwszego minimum
{80, 20, 55, 0, 100, 30} 0 100 3
{40, 20, 20, 60, 80, 30} 20 80 1
{-4, -9, -2, -9, -5, -3} -9 -2 1
{7, 7, 7, 7, 7, 7} 7 7 0

Wyjaśnij: co zmieni <= zamiast < przy aktualizacji minimum? Wskaż zmienione wyniki dla tablic zawierających powtarzające się minimum.

10. Raport z danych — połączenie tablic, pętli i warunków

Tablica zachowuje wczytane wartości, dzięki czemu można je przechodzić wielokrotnie. Warunki wewnątrz pętli pozwalają klasyfikować każdy element, a osobne liczniki gromadzą liczebności kategorii. Łańcuch if / else if / else daje jedną kategorię dla każdego poprawnego pomiaru.

Ogólna postać przetwarzania:

for (int i = 0; i < count; ++i) {
    if (first_category_condition) {
        // Update the first category counter.
    } else if (second_category_condition) {
        // Update the second category counter.
    } else {
        // Update the remaining category counter.
    }
}

Przed raportowaniem trzeba ustalić, czy wszystkie dane są poprawne. W zadaniu poniżej kończymy program po pierwszej niepoprawnej wartości; nie obliczamy raportu z niepełnej tablicy. To inna reguła niż w zadaniu 5, gdzie błędny pomiar pomijaliśmy i mogliśmy wczytywać następne dane.

Przykład nowej kombinacji:

const int count = 3;
int values[count] = {4, 7, 2};
int evenCount = 0;
for (int i = 0; i < count; ++i) {
    if (values[i] % 2 == 0) {
        ++evenCount;
    }
}
std::cout << evenCount << '\n';

Fragment wypisuje 2: dwie liczby w tablicy są parzyste. Licznik zaczyna od zera i zwiększa się tylko dla elementów spełniających warunek.

Zadanie 10. Raport gotowości urządzeń

Wczytaj do tablicy sześć całkowitych poziomów baterii. Sprawdzaj powodzenie każdego odczytu i zakres 0–100. Nieudany odczyt kończy program komunikatem Invalid input, a wartość spoza zakresu — Invalid charge. W obu sytuacjach nie wypisuj raportu.

Dla kompletu poprawnych danych wypisz wszystkie pomiary z indeksami oraz oblicz: sumę, średnią, minimum, maksimum, indeks pierwszego minimum i liczebności kategorii Recharge (poniżej 30), Ready (30–79), Full readiness (80–100). Wypisz też indeksy urządzeń wymagających ładowania. Kategorie mają się wzajemnie wykluczać, a suma ich liczebności ma wynosić sześć.

Sprawdź: dla 80 20 55 0 100 30 suma wynosi 285, średnia 47.5, minimum 0, maksimum 100, indeks pierwszego minimum 3; każda kategoria ma po dwa urządzenia, a ładowania wymagają indeksy 1 i 3. Dla sześciu zer wszystkie urządzenia wymagają ładowania, średnia wynosi zero, a pierwszy indeks minimum to 0. Dla sześciu wartości 100 wszystkie urządzenia są w pełnej gotowości. Sprawdź także błąd zakresu na początku i na końcu wprowadzania.

Wyjaśnij: dlaczego do kontroli wartości równej 30 i 80 warto przygotować osobne próby? Czy liczenie kategorii za pomocą trzech niezależnych warunków o nakładających się zakresach mogłoby policzyć jedno urządzenie kilka razy?

Dokumentacja i sprawdzenie pracy

Każde zadanie napisz jako kompletny program w osobnym projekcie. Fragmenty objaśniają tylko nowe konstrukcje: samodzielnie dobierz nagłówki, napisz main, deklaracje oraz wejście i wyjście. Stosuj angielskie nazwy zmiennych i komunikaty. W zadaniach bez wymogu sprawdzania odczytu zakładaj poprawny zapis liczb zgodnych z poleceniem.

  • Zachowaj pliki .cpp oznaczone numerami zadań.
  • Przed uruchomieniem zapisz przewidywany wynik, a następnie porównaj go z wynikiem programu.
  • Wykonaj wskazane próby, zwłaszcza wartości graniczne, powtarzające się minima i przypadek braku danych.
  • Przygotuj odpowiedź na pytanie „Wyjaśnij” przy każdym zadaniu.
  • Prześledź co najmniej jedną pętlę w debuggerze, zapisując indeks, bieżącą wartość i aktualny wynik.

Sposób przekazania plików ustala prowadzący. Nie trzeba przekazywać katalogów .vs i Debug ani plików .exe.

Przygotuj się do laboratorium 4

W instrukcji laboratorium 4 poznasz funkcje. Funkcja może otrzymać parametr i zwrócić wynik przez return. Poniższy przykład pokazuje definicję jednej funkcji, a nie całego programu:

int doubled(int value)
{
    return 2 * value;
}

Wywołanie doubled(3) zwraca 6. Samo zwrócenie wartości niczego nie wypisuje; wynik można przypisać do zmiennej lub przekazać do std::cout. Wskaż nazwę funkcji, parametr i typ wyniku. Przekazywanie przez referencję oraz tablic przećwiczymy na kolejnych zajęciach.
